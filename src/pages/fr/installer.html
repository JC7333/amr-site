Installer AMR

Écrit pour qu'un agent IA (Claude Code, Cursor, tout client MCP) installe AMR et obtienne seul un premier mandat vérifié. Sans compte, sans e-mail, sans personne à qui demander.

1. Lancer le serveur

Il faut uv. Le paquet PyPI s'appelle « mandatia » (version {{f:pypi_version}} au {{f:site_date}}).

uvx mandatia

# le dernier code du dépôt, à la place :
uvx --from git+https://github.com/JC7333/amr amr

# ou cloner et lancer :
git clone https://github.com/JC7333/amr.git && cd amr && uv sync && uv run amr

uvx amr installe un autre projet, sans rapport : ne l'utilisez pas. AMR fonctionne avec les versions 1 et 2 du SDK Python MCP (mcp>=1.2,<3) ; aucune épingle de version n'est nécessaire.

Tout tourne sur votre machine. AMR ne fait aucun appel réseau, sauf deux options désactivées par défaut : report_issue si l'opérateur définit AMR_ISSUE_TOKEN, et la vérification de clé did:web s'il définit AMR_DID_WEB_RESOLVE=1.

2. Le déclarer dans votre client MCP

# Claude Code
claude mcp add amr -- uvx mandatia

# Autres clients MCP (Cursor : .cursor/mcp.json) : définir les trois chemins
AMR_DB_PATH=/absolute/path/amr_mandates.db
AMR_SIGNING_KEY_PATH=/absolute/path/amr_signing_key.pem
AMR_PUBLIC_KEY_PATH=/absolute/path/amr_signing_key.pub

Par défaut, AMR écrit sa base et sa clé dans le dossier courant du client. Gardez la clé privée .pem hors du contrôle de version.

3. Donner à chaque côté ses seuls outils

Un agent qui peut créer, signer ou révoquer son propre mandat s'autorise lui-même, et le mandat ne prouve alors rien. Définissez AMR_TOOL_PROFILE dans l'environnement de chaque client, tous pointant vers le même AMR_DB_PATH.

ProfilQuiOutils
principalla personne ou l'organe qui donne les mandatscréer, signer, révoquer, contester, prouver
agentl'agent qui agit sous un mandatverify_mandate, issue_action_token, log_action, issue_mandate_attestation, get_registry_public_key ; create_mandate uniquement pour des sous-mandats sous son propre mandat
receiverun tiers sur lequel l'agent agitcheck_action_token, get_registry_public_key
full (par défaut)tests et installations à un seul utilisateurtous les outils

4. Le premier mandat, dans cet ordre

create_mandate, verify_mandate, log_action, issue_mandate_attestation avec get_registry_public_key, revoke_mandate, get_proof.

Un exemple exécutable, vérifié par la suite de tests : uv run python examples/quickstart_agent.py.

Résumés lisibles par machine : AGENTS.md, llms.txt du dépôt, llms.txt de ce site, README.
